# Codex++ 1.0.6

This patch keeps tweak-managed MCP server configuration in the active Codex home when `CODEX_HOME` is set.

## Fixes

- Sync managed MCP servers into `<CODEX_HOME>/config.toml` when a custom Codex home is configured.
- Keep using `~/.codex/config.toml` when `CODEX_HOME` is unset or empty.
- Include the corrected path in the packaged runtime used by install and repair.

## Verification

- Windows full test suite: 215 passed, 7 platform skips, 0 failures. Build passed.
- Added three regressions for custom, unset, and empty `CODEX_HOME` values.
- Checked the generated runtime path expression against the same three cases and verified managed MCP configuration writes in isolated temporary directories.
- Status and doctor checks passed on the existing Windows installation with an intact patch before deployment of the 1.0.6 runtime.
- Codex app-server checks confirmed configuration, session, and skill loading from a custom `CODEX_HOME` with both installed CLI distributions. The live desktop runtime has not been switched to the new home for this verification.
- A complete install/doctor/repair/uninstall cycle on a real Codex installation has not been run for this patch. Existing installer and repair behavior is covered by the full automated suite; other platforms have not been manually verified.

## Dependency audit

The audit reports six affected dependency packages (one critical, four high, and one low): `tar`, `@xmldom/xmldom`, `brace-expansion`, `electron`, `extract-zip`, and `esbuild`. Dependency versions are unchanged from 1.0.5; these advisories are not resolved by this patch.

## Upgrade

Run `codexplusplus update`, then fully quit and reopen Codex to load the updated runtime. Set `CODEX_HOME` in the environment used to launch Codex before reopening it.
