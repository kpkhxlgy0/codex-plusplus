# Codex++ 1.0.3

This patch fixes excessive file I/O caused by repeated Settings navigation injection and log trimming.

## Fixes

- Native Settings scrollers no longer trigger a remove-and-reinsert loop for Codex++ navigation. Composer overlays remain excluded from injection.
- When a runtime log reaches its 10 MiB cap, trimming now reads only the retained tail and frees roughly half the file for new entries. Small appends no longer read and rewrite nearly 10 MiB each.
- Bridge diagnostics now recognize ASAR window-services markers on Windows, where archive listings use backslashes.
- Regression tests correctly handle Windows path escaping and skip Linux executable-permission fixtures on Windows.

## Verification

- A full 10 MiB log followed by 40 small entries required approximately 400 MiB of reads and 400 MiB of writes before the fix, versus approximately 5 MiB each after the fix. These are measured file-I/O totals for that workload, not sustained physical-disk speeds.
- Regression tests cover log growth, retained history, oversized entries, DOM stability, native sidebar remounts, and composer overlay exclusion.
- The dependency audit still reports six advisories in existing dependencies. Dependency upgrades are outside this patch.

## Upgrade

Run `codexplusplus update`, then fully quit and reopen Codex to load the new runtime.
