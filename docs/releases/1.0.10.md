# Codex++ 1.0.10

Successful Windows Store installation and repair now automatically remove unused older application mirrors,
preventing historical copies from accumulating under `%LOCALAPPDATA%/codex-plusplus/store-apps`.

- Keep the current app, directories referenced by running processes, newer versions, other package families and
  architectures, and unrecognized directories.
- Verify persisted installation state, native process information, exact directory boundaries and reparse points
  before deletion. An uncertain or failed check preserves the directory.
- Cover native update and watcher repair through the same successful install/repair paths. Failed or paused
  upgrades do not trigger cleanup. Cleanup errors are reported without undoing a successful upgrade.
- Recognize the protected Codex sandbox service only through matching Windows service and registered package
  metadata. No process termination or privilege change is used.
- Preserve runtime files, tweaks and recovery backups.

Verification: full build passed; 381 tests, 372 passed and 9 platform skips. Independent review found no material
issues. The built helper removed four authorized old mirrors on the development machine, about 9.46 GiB in total
file size, while the current application archive and installation state remained unchanged.

Update through `codexplusplus update`. Windows Store users should close Codex before installing or repairing.
No new configuration flag is required for automatic cleanup.
